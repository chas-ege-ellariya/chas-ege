# Подготовка пачки PR одной командой: `dev/review-batch.js`

Заменяет ручную подготовку из [ревью пачки пуллреквестов](review_batch.md)
(«1. Подготовка», карта конфликтов из «3. Карта пачки») и
[«Несколько PR сразу»](how_to_review_PR.md#несколько-pr-сразу-отдельный-git-worktree-на-каждый):
каждому PR — своя рабочая копия, слитая с `devel`, своя сборка и `npm test`,
эталон — такая же копия `devel`.

```bash
node dev/review-batch.js 3711 3717 3773 3798      # подготовить пачку: копии, сборки, тесты, таблица
node dev/review-batch.js --no-build 3711 3717     # только карта: смёржен ли, конфликты — за секунды
node dev/review-batch.js --clean                  # удалить рабочие копии
```

Карта (`--no-build`, около секунды):

```
PR    голова     состояние   слияние с devel          тестов  замечания
3148  497899873  не смёржен  конфликт: lib/canvas.js
3711  090294d4c  не смёржен  чисто
3714  724f97280  не смёржен  чисто
3769  42668051d  смёржен
3773  e299d2c7e  не смёржен  чисто

Конфликты между PR пачки (каждый слит с devel):
  3711 и 3714: zdn/matege2024b/11/main.js
  Не проверялись пары с 3148: сначала конфликт с devel.
```

Со сборками добавляются строка `devel` и число тестов:

```

3711    090294d4c  не смёржен  чисто                    1389 (+16)

```

## Что делает

1. Скачивает `upstream/devel` и головы всех PR (`refs/pull/*/head`).
2. Смёржен ли PR — голова предок `devel`. Закрыт ли без мержа, по git не узнать:
   это запрос состояния из «Отсева» в [ревью пачки](review_batch.md).
3. Сливается ли PR с `devel` и какие пары PR конфликтуют.
   **Пары сравниваются уже слитыми с `devel`**: «PR a + devel» против «PR b + devel»
   (`git merge-tree` по коммитам, которые нигде не сохраняются, кроме объектов в `.git`).
   Сравнение голов «в лоб» шумит: голова со старой базой «конфликтует» с другими PR
   из-за правок `devel`, которых нет в ней самой (так 3148 «конфликтовал» с 3800 в `lib/canvas.js`,
   хотя 3800 этот файл не трогает). PR, который не сливается с `devel`, в пары не идёт.
4. Для каждого не смёрженного PR — рабочая копия `../review-batch/pr-N` **без ветки**
   (`git worktree add --detach`), `node_modules` — симлинком на основную копию,
   слияние с `devel` — коммит только в этой копии. Если слияние даёт конфликт,
   собирается голова PR как есть, и число её тестов сравнивают с её базой (хеш в таблице).
5. `grunt` и `npm test` во всех копиях, по `--jobs` (4) одновременно;
   вывод — в `review-batch.log` каждой копии.
6. Таблица: число тестов против `devel`, «Не удалось загрузить», упавшие тесты,
   бандл без `chas-lib` (меньше 4 МБ: запустить `grunt` в копии ещё раз).

Семь копий (шесть PR и `devel`) при `--jobs 4` собираются и тестируются около трёх минут.

## После

Сборки остаются для прогонов шаблонов, каждая со своим бандлом:

```bash
(cd ../review-batch/pr-3711 && node build/dev/run-node-template.js --filepath zdn/matege2024b/11/506579.js --iterations 300 --seed 1 --json --quiet > /tmp/506579.json)
node ../review-batch/devel/build/dev/run-node-template.js --eval '(12).nod(18)'
```

`--filepath` отсчитывается от текущей папки: чтобы прогнать шаблон из PR, а не из основной копии,
команду запускают в копии PR.

Повторный запуск пересоздаёт копии тех же PR (и `devel`) с нуля: внесённое в них руками пропадёт.

## Ключи и код возврата

- `--remote R` (`upstream`), `--base B` (`devel`), `--dir D` (`../review-batch` от корня репозитория),
  `--jobs N` (4), `--no-build`, `--clean`.
- Папку в `--dir`, которая не рабочая копия этого репозитория, скрипт не трогает и останавливается.
- `0` — всё собралось и тесты прошли; `1` — ошибка ключей или git;
  `2` — у кого-то сборка или тесты не прошли, файл тестов не загрузился
  или тестов меньше, чем в `devel`.

## Что нужно

- git 2.38+ (`merge-tree --write-tree`).
- Для сборок — `grunt-cli` и `canvas` в `node_modules` основной копии, одной командой:
  `npm install --no-save grunt-cli canvas` (см. «Подводные камни» в [ревью пуллреквеста](how_to_review_PR.md)).
  `npm install` в рабочих копиях не запускать: `node_modules` у них общий.
